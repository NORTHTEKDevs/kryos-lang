### Task 1.3: Fix LLVM SSA bug — alloca/store/load for mutable variables

This is the critical bug. The LLVM backend emits `%_N = add type val, 0` for every assignment, but LLVM SSA requires each `%_N` to be defined exactly once. When a mutable variable is reassigned in a loop, this crashes.

**Fix strategy:** For every local that is mutable OR assigned more than once, emit:
1. `alloca` in the entry block
2. `store` on every assignment
3. `load` on every use

Immutable locals assigned exactly once keep direct SSA names (no regression).

**Files:**
- Modify: `compiler/crates/kryos-codegen-llvm/src/codegen.rs`
- Test: `compiler/crates/kryos-codegen-llvm/tests/codegen.rs`

**Step 1: Write the failing test**

Add to `compiler/crates/kryos-codegen-llvm/tests/codegen.rs`:


Expected: FAIL — `alloca` not found in output.

**Step 3: Implement alloca/store/load in LlvmCodegen**

In `codegen.rs`, the changes needed:

1. Add a `mutable_locals: HashSet<u32>` field to `LlvmCodegen` that tracks which locals need alloca.

2. In `emit_function_as()`, after building the local type map, pre-scan the function to find locals that are:
   - Marked as `mutable: true` in MirLocal, OR
   - Assigned more than once across all blocks

3. At the start of the entry block (`bb0:`), emit `%_N.addr = alloca <type>` for each mutable local. Then if the local is a parameter, emit `store <type> %_N, ptr %_N.addr`.

4. In `emit_assign()`:
   - If dest is mutable: emit the computation to a temp `%tN`, then `store <type> %tN, ptr %_N.addr`
   - If dest is immutable: keep current behavior (direct SSA def)

5. In `operand_to_llvm()`:
   - If `Operand::Local(id)` and id is mutable: emit `%tN = load <type>, ptr %_N.addr` and return `%tN`
   - If immutable: return `%_N` as before

6. In `emit_terminator()` for `Return(Some(op))`: use the same load logic for mutable operands.

**Key implementation details:**

The entry block alloca approach:
```llvm
bb0:
  %_0.addr = alloca i64    ; sum (mutable)
  %_1.addr = alloca i64    ; i (mutable)
  store i64 0, ptr %_0.addr
  store i64 0, ptr %_1.addr
  br label %bb1

bb1:
  %t0 = load i64, ptr %_1.addr
  %_2 = icmp slt i64 %t0, 10
  br i1 %_2, label %bb2, label %bb3

bb2:
  %t1 = load i64, ptr %_0.addr
  %t2 = load i64, ptr %_1.addr
  %t3 = add i64 %t1, %t2
  store i64 %t3, ptr %_0.addr
  %t4 = load i64, ptr %_1.addr
  %t5 = add i64 %t4, 1
  store i64 %t5, ptr %_1.addr
  br label %bb1

bb3:
  %t6 = load i64, ptr %_0.addr
  ret i64 %t6
```
